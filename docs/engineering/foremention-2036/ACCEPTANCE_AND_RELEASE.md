# Acceptance before customer release

The full product job is: approved buyer questions → authorized collection → source provenance and human review → decision → approved work → permitted effect → comparable later cycle → outcome review. A passing build or synthetic fixture does not prove this whole job.

Required release proof includes:

- Exact repository/build identity and documented PR integration; no draft-only code counted as merged.
- Disposable PostgreSQL/Supabase replay, two tenants, sibling projects, revoked roles and service-role boundary tests.
- Known collection protocol with provider/surface/method/model revision/retrieval identity, correct missing/failed/abstaining denominators and no invented historical values.
- Safe URL/DNS/redirect/private-address/streamed-byte boundaries before external evidence fetching.
- Immutable approved claims and evidence versions; expiry, retraction and private-source restrictions.
- Approval of the exact content, destination, actor scope, budget and version before effects; atomic claim, fenced settlement and uncertain-delivery reconciliation.
- Billing/entitlements, quota reservations, cancellation/retry and recovery without duplicate charges/effects.
- Browser workflow using disposable accounts: persistence, refresh, review/approval, error/empty/blocked states, keyboard and accessibility.
- Dependency/license/NOTICE/security/SBOM checks, no secrets in source or artifacts, tested backup/restore and separately authorized release.

Evaluate all 15 adoption audits before installing a serious new component: existing overlap; identity/origin; functional depth; runtime compatibility; commercial/transitive rights; security/supply chain; integration complexity; reproducibility; duplication; agent/tool authority; lineage/tenancy/rights; actual operating cost; resilience/resources; maintenance/portability; UX/accessibility.

Unknown is not a pass. Keep the existing implementation when reuse does not show a better complete workflow. All 14 product systems remain in the private handoff's traceable roadmap. No roadmap item becomes complete merely because its report exists.
