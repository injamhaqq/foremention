# Foremention Company OS Gap Audit

Date: 2026-10-02

## Correction

The initial Unified Capability Spine was intentionally a **technical integration spine**.
It did not by itself represent the complete autonomous company.

The complete design has two independent axes:

1. **Company Domains** — what the company must be able to do.
2. **Capability Infrastructure** — how agents/tools safely perform that work.

A complete build must cover both.

## Non-negotiable consolidation rule

The Company OS must behave as **one system**:

- one canonical company truth: Supabase;
- one durable orchestrator: Inngest;
- one Foremention action/approval/audit path;
- one tenant/project boundary model;
- one evidence standard;
- one capability registry;
- one secrets boundary;
- one founder decision surface.

External systems are adapters, sidecars, CI tools, or reference libraries.

## Coverage invariant

A build is incomplete if it implements the agent infrastructure but leaves an operating domain with no:
- owner agent/network;
- skills;
- tools;
- data contract;
- events/triggers;
- policy;
- metrics;
- evidence;
- escalation;
- failure/rollback behavior.

## Unknown-unknown invariant

This document cannot be the final list.

The production Company OS must continually compare:
- Foremention;
- current GitHub/open-source capabilities;
- model/API changes;
- competitors;
- enterprise buyer expectations;
- security threats;
- regulations;
- funding programs;
- high-performing company operating practices;

and create a reviewed proposal whenever a material missing or obsolete capability is detected.
